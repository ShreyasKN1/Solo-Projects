Netflix-> 10 minutes Window Interview Question:


Functional Requirements:
	-> user can browse movies/series.
	-> search for content
	-> play video
	-> resume playback
	-> recommendations
	-> Manage Subscription Plan.

Non Functional Requirements:
	-> Multiple number of concurrent users
	-> low startup latency(<30 ms)
	-> Minimal buffering
	-> Global scale
	-> High Availability(99.99%)
	

FLow:
	Internal Architecture divided into 3
		|
                 -> Control Plane:
			User service
			Subscription Service
			ContentMetadata Service
			Watch history Service
			Recommendation Service
			Trending/Rating Service
			
		-> Data plane(video streaming)
			Encoding pipelines
			CDN
			Video Storage


		-> Analytics Plane
			A/D testing
			logging
			backtrack analysis


User-> API Gateway -> Backend(metadata APi)
	  |
	  |->CDN -> Edge-> receive in video chunks

Backend-> who you are, in what location video is present, subscription checks.
CDN-> content delivery by video chunks



Video Storage-> usually stored in s3 buckets
	S3-> encoding pipeline-> multiple resolutions(144p,240p,360p..4k)-> video chunks based stored like 5-20 seconds in every resolution-> Because of adaptive bitrate streaming-> chunks will be pulled and quality improves based on network connection->formatted in HLS, mpeg-dash.(similar to youtube codec)

Database tables:
	Content Table
		-> content id
		-> title
		-> genre
		-> rating
		-> regionAvailablity

	user table
		-> userid
		-> subscription plan
		-> region

	Watch History table
		userid
		contented
		one -> last watched position
		timestamp

Shard DB by usedId(high writes will be there for watch history).
Also read heavy workloads for metadata so replication needed.


Flow-> user-> searches for video/series-> selects a video-> backend verifies subscription plan-> backend gets playback url(CDN signed URL)-> user starts getting chunks of that video-> Adaptive Bitrate adjusted dynamically based on network-> Playback analytics send asynchronously

signed URL prevents unauthoritive streaming.


Scalability and Better Setup:
*CDN offloading 90% traffic
*Stateless service behind load balancers.
*Database replication
*Multi region deployment
*Autoscaling groups

Strong COnsistency-> Manage account as well as billing/subscription
Eventual COnsistency-> Analytics, Trending, recommendations

Recommendation System we can create a label-> use an ML algo to predict the recommendation per user based on label.

user-> DNS-> locate the nearest edge location CDN-> cachehit /miss-> receive content-> miss hit original storage.

if one fails-> go to next nearest edge location
if encoding pipeline fails retry pipeline
Trending topics must be pre warmed.

when cache/CDN used we should also worry on cache edging, cache validation, region replication, trending hot topic distribution.
