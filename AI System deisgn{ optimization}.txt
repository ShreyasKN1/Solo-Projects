AI System deisgn{ optimization} :



** Why is it called optimization?

Answer:
Optimization means improving a system to achieve the same goal while using fewer resources or less time.
In AI, optimization can happen at different stages:
->Training Optimization: Reduce loss while training the model.
->Inference Optimization: Produce the same output faster or cheaper.

Example
Without optimization:

User->
LLM->
Answer (4 sec)

With optimization:

User->
Optimized Inference->
LLM->
Answer (2 sec)

Examples of inference optimizations:

1)Speculative Decoding
2)Quantization
3)KV Cache
4)Continuous Batching


** Is Speculative Decoding an ML algorithm?

Answer:

No.
It is an Inference Optimization Technique, not a Machine Learning algorithm.
Some of the Inference Optimizations techniques are:

1)Speculative Decoding
2)KV Cache
3)Quantization
4)Continuous Batching

These techniques improve speed and cost but do not train or change the model.



** What is Speculative Decoding?

Answer:

Instead of letting the large LLM predict one token at a time, a smaller model predicts several future tokens.

The larger model verifies them in one forward pass.

If correct -> accept all tokens.

If incorrect -> reject from the first mismatch and continue normally.

Advantages would be:
Reduce latency
Increase throughput
Reduce GPU cost

Used by many production LLM serving systems.




** What AI-specific things should be considered before deploying to production?

Answer:

Unlike normal backend applications, AI systems require additional production considerations.
Model Loading
Large models can take minutes to load.

Need:

=>Startup probes
=>Readiness probes
=>Warm-up endpoints
=>Cold Start

Avoid first requests waiting for model loading.

Solutions:

=>Warm instances
=>Minimum replicas
=>Dedicated inference servers
=>GPU Management

*Need to consider:
GPU memory
CUDA version
Drivers
VRAM availability
Continuous Batching

=>Combine multiple user requests into a single GPU execution.

Benefits:

->Better GPU utilization
->Higher throughput
->Lower cost
->Quantization

=>Convert model precision:

FP16 -> INT8 -> INT4

Benefits:

->Less memory
->Faster inference

Trade-off:

->Slight accuracy loss
->KV Cache

=>Cache previous attention states.

Benefits:
->Avoid recomputing previous tokens
->Faster text generation
->Speculative Decoding

=>Use a small draft model and large verification model.

Benefits:
->Faster inference
->Lower latency
->Rate Limiting

Prevent GPU overload by limiting requests.

=>Prompt Caching
Reuse responses for repeated prompts.

Benefits:

->Lower cost
->Faster responses
->Streaming

Return tokens as they are generated instead of waiting for the entire response.

Improves perceived latency.

=>Model Versioning

Maintain:
v1
v2
v3

Allows rollback if a newer model performs worse.

=>A/B Testing

Compare different models in production.

Measure:
->Accuracy
->Latency
->Cost
->User satisfaction
->Cost Optimization

Use different models depending on task complexity.

Example:

Simple FAQ -> Small model

Complex reasoning -> Large model
